# CM数字板测问题闭环

## PS初始化没有执行（已修复，r5三轮通过）

XSCT对已停止ARM执行stop返回Already stopped；原脚本中断但进程仍返回0，导致主机误判PS初始化成功。FCLK0实际读回0x00101800，与本工程要求的0x00200500不符，ILA首先表现为采集数据错误。

init_ps.tcl仅容许明确的Already stopped状态；其他异常统一exit 1。初始化和后配置均校验FCLK0/IOPLL读回值。主机除退出码外还要求独立PASS标记，逐轮保存ps_init.log、ps_post.log。修复后原44项及前26项新增CM场景均已运行通过，但这一部分结果只作为定位记录。

## ILA扩展信号拼接缺少填充（已修复，r5三轮通过）

原低位观察字段实际使用235位，原256位端口高21位为保留填充。扩至384位时未保留中间的21位，导致脚本预期的CE[256]和sleep_state[260:257]位置错误，休眠场景等待错误触发条件。

现场读取到sequence完成、sleep_count=1、wake_count=1；重新即时触发的ILA也显示主时钟已恢复。路由检查点确认dbg_hub/clk、ILA及JTAG均来自常开时钟，不能把本次等待归因于调试Hub接入停钟域。

修复生成器中的21位填充，在tb_board_suite增加逐周期物理观察位断言；重新执行27项仿真并完整构建。采集脚本改用已在本机确认的FULL状态与5秒墙钟期限，避免wait_on_hw_ila的分钟级超时。失败日志和现场波形位于build/board/failures/，不得用于本轮通过证明。

本文件记录故障原因；功能状态以CM_ACCEPTANCE.md和同镜像的三轮板测为准。用户已排除本轮长压力，压力状态独立记录，不作为功能通过的替代证据。

## 拒绝休眠场景的采集条件（已修复，r5三轮通过）

cm_sleep_unsafe_rejected用于验证拥有任务时拒绝休眠。其序列和数据/事件检查完成，但原采集脚本因场景名称以cm_sleep开头，错误地等待停钟状态，5秒超时。现场sequence状态0xc2、LL错误为0，说明未进入休眠正是预期行为。

该场景改用序列启动触发，其余真实休眠场景继续检查物理停钟状态。RTL、镜像不变，只封存了更新后的运行脚本。完整日志、寄存器快照和此前实际休眠波形保存在build/board/failures/20261106_0316/；本次运行不计入三轮通过结果。

## CCM私有缓存端口推断（已修复）

r4综合发现原CCM内部读写和空闲主机读写分写在不同分支，工具无法利用其互斥关系，512×32私有载荷RAM被映射为LUTRAM。单独合并读口仍不足以形成BRAM；必须同时在RAM外复用写地址、写数据和字节使能，明确只有一个读口和一个写口。该调整未修改128KiB EM或对象布局。

修复后独立xc7z100综合得到ccm/memory_reg这一物理BRAM，综合0错误、0关键告警、0普通告警；结果保存在build/cm_crypto_bram.json、.rpt、.log。读数据仅在read_valid时有效，同址空闲读写为read-first，忙时主机访问不影响引擎，复位不清RAM。tb_crypto增加相应检查，原独立密文/MIC断言保留。

同时为专用停钟原语明确SIM_DEVICE=7SERIES，并修正两处声明顺序告警。r4构建主动停止并保留在临时目录SLECM-20261106-r4，仅作诊断，不作最终板测证明；最终镜像需由全部修复后的源码重新实现。

新增的真实BRAM经过定向REQP-1839/1840检查后，确认仍需隔离CCM异步FSM和调用者控制。修复使用独立、同步复位的地址/数据/字节写/使能寄存级，而非屏蔽DRC。内部RAM读增加等待状态，外部读有效改为两拍，所有调用者继续等read_valid；最终MIC写完成后才置DONE。复位采样边沿允许此前已接受的一笔写提交，不清整块RAM，旧读有效不会跨复位交付。最新定向综合及两项异步控制DRC已通过，对应日志及源哈希在build/cm_crypto_bram.*。

## Vivado门控原语展开属性提示

r5源端BUFGCE已显式指定SIM_DEVICE=7SERIES。Vivado 2020.2展开为BUFGCTRL后仍会对展开对象报告默认ULTRASCALE值并自动修正，不能把这个工具提示称为源端参数尚未设置，也不能仅凭自动修正就断言最终配置正确。后实现检查因此增加真实原语SIM_DEVICE=7SERIES断言，同时保留专用同步CE及JTAG/ILA常开连接检查；结果写入debug_clocks.rpt。若最终属性不符，构建仍判失败，不屏蔽该消息。

最终r5物理检查已通过：真实原语为BUFGCTRL，BUFGCE展开标记有效，同步CE配置及SIM_DEVICE=7SERIES均满足要求。三轮新镜像板测均87/87通过，代表性停钟ILA稳定区分别为995/993/997点。CCM缓存为真实BRAM，整板没有REQP-1839/1840异步控制违规；28项仿真与实际镜像源哈希一致。功能验收已闭环，长压力按用户要求排除，未称为通过。
